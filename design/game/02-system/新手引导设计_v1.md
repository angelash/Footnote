## 📌 设计理念

### 核心原则

1. **叙事融合**：引导是故事的一部分，不是额外的教程层
2. **渐进揭示**：信息按需呈现，避免一次性灌输
3. **尊重玩家**：假设玩家聪明，提供最小必要提示
4. **允许失败**：通过后果学习，而非强制正确

### 设计哲学

> 最好的引导是让玩家感觉自己"发现"了玩法，而非"被教会"了玩法。  
> 在《备注》中，不理解也是体验的一部分——这与世界观一致。

## 1. 引导策略总览

### 1.1 引导层次

| 层次 | 内容 | 呈现方式 | 强制性 |
|------|------|----------|--------|
| **L0 基础操作** | 移动、交互 | 环境暗示 | 隐性必须 |
| **L1 核心机制** | 能力使用 | 剧情授信 | 显性必须 |
| **L2 进阶技巧** | 组合使用 | 渐进发现 | 可选 |
| **L3 隐藏机制** | R/P/W、伏笔 | 不引导 | 自行发现 |

### 1.2 引导时机分布

| 章节 | 引导内容 | 密度 |
|------|----------|------|
| **C0 序章** | 基础移动、交互、对话 | 高 |
| **C1 第1章** | 解谜逻辑、卡片收集 | 中 |
| **C2 第2章** | 深度感知 | 中（能力教学） |
| **C3 第3章** | 深度介入 | 中（能力教学） |
| **C4 第4章** | 时间干预 | 中（能力教学） |
| **C5 第5章** | 无新引导 | 低 |
| **CF 终章** | 无新引导 | 无 |

### 1.3 引导完成率目标

| 内容 | 目标完成率 | 允许跳过 |
|------|------------|----------|
| 基础移动 | 100% | 否 |
| 对话交互 | 100% | 否 |
| 深度感知 | 95% | 否 |
| 深度介入 | 90% | 是（可绕过） |
| 时间干预 | 85% | 是 |
| 卡片查看 | 80% | 是 |

## 5. 引导反馈系统

### 5.1 引导状态追踪

```typescript
interface ITutorialProgress {
  // 基础操作
  hasMovedFirst: boolean;
  hasInteractedFirst: boolean;
  hasDialogueFirst: boolean;
  hasMadeChoiceFirst: boolean;
  hasInspectedFirst: boolean;
  
  // 能力使用
  hasUsedDepthPerception: boolean;
  hasUsedDepthIntervention: boolean;
  hasUsedTimeIntervention: boolean;
  
  // UI使用
  hasOpenedBackpack: boolean;
  hasOpenedMap: boolean;
  hasOpenedTime: boolean;
  hasSavedManually: boolean;
  
  // 完成标记
  tutorialPhaseComplete: 'none' | 'basic' | 'perception' | 'intervention' | 'time' | 'full';
}
```

### 5.2 引导跳过机制

```
对于二周目玩家或明确表示要跳过的玩家：

进入游戏时检测:
├── 存在完成存档 → 提供"跳过引导"选项
└── 新玩家 → 正常引导流程

跳过引导后:
├── 所有UI直接可用
├── 所有能力按剧情正常解锁
├── 不显示操作提示
└── 保留叙事内容（不跳过对话）
```

### 5.3 卡住检测与帮助

```yaml
# 卡住帮助配置
stuck_detection:
  rules:
    - name: idle_too_long
      condition: player_idle > 30s
      help:
        type: gentle_hint
        text: "需要帮助吗？试试检查周围的环境"
    
    - name: same_zone_too_long
      condition: zone_time > 300s && no_progress
      help:
        type: specific_hint
        text: "{zone_specific_hint}"  # 从Zone配置读取
    
    - name: failed_multiple_times
      condition: same_action_failed >= 3
      help:
        type: solution_hint
        text: "也许需要换一种方法..."

  cooldown: 60s  # 同一提示不重复出现的间隔
```

## 6. 无引导区域设计

### 6.1 设计原则

某些内容**故意不引导**，让玩家自行发现：

| 内容 | 不引导原因 |
|------|------------|
| R/P/W计数器 | 隐藏机制，发现是惊喜 |
| 伏笔系统 | 自行连接更有成就感 |
| 无收益选择 | 做选择时不应有功利心 |
| 多结局条件 | 自然游玩获得，非攻略 |
| 重返变体 | 探索发现 |

### 6.2 隐性引导

虽然不直接引导，但通过设计暗示：

| 内容 | 隐性引导方式 |
|------|--------------|
| 无收益选择 | 栖蓝的言行示范 |
| 系统变化 | 语气/格式微妙变化 |
| 伏笔关联 | 卡片描述中的线索 |
| 结局走向 | NPC对玩家行为的反应 |

## 7. 引导文案规范

### 7.1 文案风格

| 类型 | 风格 | 示例 |
|------|------|------|
| **操作提示** | 简洁、动词开头 | "长按屏幕激活感知" |
| **系统说明** | 克制、系统语气 | "新功能已解锁" |
| **叙事融合** | 角色口吻 | "试试你的新能力" |
| **警告提示** | 严肃、后果明确 | "⚠ 此操作不可撤销" |

### 7.2 文案长度

| 场景 | 最大字数 | 说明 |
|------|----------|------|
| 浮动提示 | 15字 | 快速阅读 |
| 教学面板 | 50字 | 分段显示 |
| 确认对话 | 30字 | 核心信息 |
