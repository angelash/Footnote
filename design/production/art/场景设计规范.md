## 1. Kit 套件系统

### 1.1 Kit 的概念

**Kit = 同一主题的完整资产集合**

```yaml
kit_definition:
  purpose: "让任何新主题只要按清单补齐，就能拼出完整关卡"
  structure:
    - "Ground Base（地面基底）"
    - "Transitions（过渡边）"
    - "Overlays（覆盖层）"
    - "Structures（结构件）"
    - "Props（物件）"
    - "Foliage（植被）"
    - "Boundaries（边界封口）"
```

### 1.2 《备注》六大Kit（对应六大区域）

| Kit ID | 名称 | 风格关键词 | 主配色 |
|--------|------|------------|--------|
| KIT_RESIDENTIAL | 居住环 | 日常、温暖、人味 | 暖灰+柔光 |
| KIT_MUNICIPAL | 市政环 | 秩序、流程、冷硬 | 蓝灰+金属 |
| KIT_ARCHIVE | 档案巷 | 旧纸、尘封、密集 | 褐+米白 |
| KIT_CLINIC | 诊疗台 | 无菌、边界、压抑 | 白+淡绿+警告红 |
| KIT_RITUAL | 礼堂街 | 仪式、神秘、古旧 | 紫+金 |
| KIT_EDGE | 边缘断口 | 异常、压力、扭曲 | 深黑+荧光裂隙 |

### 1.3 Kit 最小交付清单

**每个Kit必须包含（DoD）**

```yaml
kit_minimum_requirements:
  ground_base:
    count: "4类 × 6变体 = 24张"
    types: ["主地面", "次地面", "特殊1", "特殊2"]
    note: "每类6变体避免重复感"
  
  transitions:
    priority:
      P0: "必须 - 主地面↔次地面"
      P1: "建议 - 特殊地面过渡"
    pieces_per_transition: 16  # 16片Blob
  
  overlays:
    count: "≥30个"
    categories:
      - "落叶/碎片（5）"
      - "裂纹/划痕（5）"
      - "苔藓/污渍（5）"
      - "小石子/杂物（5）"
      - "草尖/植物点缀（5）"
      - "叙事痕迹（5）"  # 《备注》特有
  
  structures:
    walls:
      - "直段（横/竖）"
      - "外角（4）"
      - "内角（4）"
      - "端头（2）"
      - "门洞（1+）"
      - "窗（2+）"
    bridges: "如需要：直段+两端"
    stairs: "如需要：台阶/坡道"
  
  props:
    count: "≥40个"
    categories:
      - "叙事道具（10）"     # 书、信、录音机...
      - "环境杂物（15）"     # 箱子、桶、石头...
      - "导航指示（5）"      # 路牌、门牌、灯...
      - "可交互机关（10）"   # 开关、锁、箱子...
  
  foliage:
    count: "≥12个"
    types:
      - "灌木（4）"
      - "树（4）- 必须拆：树干+树冠"
      - "花/蘑菇/小植被（4）"
  
  boundaries:
    - "地图边缘封口块"
    - "角落封口块"
    - "不可走区域视觉"
```

## 3. 场景拼装语法

### 3.1 蓝图系统 (Blueprint System)

**先做蓝图，再做渲染**

```yaml
blueprint_types:
  grid_layout:
    name: "网格占位图"
    size: "12×21 TU（一屏）"
    content: "纯色块表示：地面/墙/水/不可走"
    purpose: "锁布局（AI不许改）"
    format: "PNG with fixed colors"
  
  height_map:
    name: "高度层级图（可选）"
    content: "0/1/2 Level用不同灰度"
    purpose: "锁遮挡逻辑"
  
  object_placement:
    name: "物件占位图"
    content: "简单形状标注物件footprint"
    purpose: "每个物件一个颜色ID"
```

### 3.2 蓝图颜色规范

```yaml
blueprint_colors:
  ground:
    grass: "#4CAF50"      # 绿
    dirt: "#8B4513"       # 褐
    stone: "#9E9E9E"      # 灰
    water: "#2196F3"      # 蓝
  
  collision:
    walkable: "#FFFFFF"   # 白
    blocked: "#000000"    # 黑
    slow: "#FFEB3B"       # 黄
  
  objects:
    prop_small: "#FF9800"
    prop_medium: "#FF5722"
    prop_large: "#F44336"
    structure: "#9C27B0"
    foliage: "#8BC34A"
```

### 3.3 分Pass渲染流程

```yaml
render_passes:
  pass_1_ground:
    content: "只渲地面（Base + Transition）"
    forbidden: "任何大物件"
  
  pass_2_structures:
    content: "墙、桥、屋子（按模块拼装）"
    forbidden: "小装饰"
  
  pass_3_props:
    content: "按footprint图摆放"
    limit: "每屏不超过12个主要物件"
  
  pass_4_overlays:
    content: "落叶、苔藓、轻微脏迹"
    allowed: "这一步才允许'随机感'"
  
  why_separate:
    - "不分Pass，AI会把装饰和结构混成一团"
    - "分Pass后资产可独立修改和复用"
```

## 4. 层级与遮挡系统

### 4.1 八层渲染系统

```yaml
render_layers:
  layer_0:
    name: "Ground Base"
    z_index: 0
    content: "地面基底"
  
  layer_1:
    name: "Ground Transition"
    z_index: 1
    content: "地面过渡边"
  
  layer_2:
    name: "Ground Overlay"
    z_index: 2
    content: "地面覆盖/贴花"
  
  layer_3:
    name: "Shadow"
    z_index: 3
    content: "阴影层（引擎/分离）"
  
  layer_4:
    name: "Object Base"
    z_index: 4
    content: "物件底座（箱子、石头、树干）"
  
  layer_5:
    name: "Character"
    z_index: 5
    content: "角色"
  
  layer_6:
    name: "Foreground Occluder"
    z_index: 6
    content: "前景遮挡（树冠、屋檐、拱门上沿）"
  
  layer_7:
    name: "Screen FX"
    z_index: 7
    content: "屏幕特效（雾、暗角、转场）"
```

### 4.2 遮挡件交付规范

**任何会挡住角色的东西必须拆成两张**

```yaml
occluder_rules:
  split_requirement:
    base: "主体底座（Layer 4，不遮挡角色）"
    occluder: "遮挡卡（Layer 6，只画挡住部分）"
  
  examples:
    tree:
      base: "树干底座 → Layer 4"
      occluder: "树冠 → Layer 6"
    building:
      base: "建筑主体 → Layer 4"
      occluder: "屋檐前沿 → Layer 6"
    arch:
      base: "拱门柱子 → Layer 4"
      occluder: "拱门上沿 → Layer 6"
  
  specs:
    pivot: "与底座相同footprint锚点"
    alpha: "边缘透明度统一（不要一张硬一张软）"
```

## 6. 交互状态系统

### 6.1 可交互物件四态

**所有可交互物件必须有4个状态**

| 状态 | 名称 | 描述 | 资产要求 |
|------|------|------|----------|
| S0 | 默认态 | 未互动 | 静态图×1 |
| S1 | 提示态 | 玩家靠近 | 统一高亮Overlay |
| S2 | 进行态 | 互动过程 | 2-3帧（可选） |
| S3 | 完成态 | 互动后 | 静态图×1（与S0不同） |

### 6.2 执行策略

```yaml
interaction_assets:
  s0_default:
    type: "静态图"
    count: 1
    example: "door_closed.png"
  
  s1_highlight:
    type: "统一高亮Overlay"
    shared: true  # 所有物件共用
    components:
      - "outline_overlay.png"     # 细轮廓发光
      - "icon_prompt.png"         # 小图标提示
      - "pulse_animation.json"    # 透明度呼吸（引擎实现）
  
  s2_action:
    type: "可选动画帧"
    count: "2-3帧 或 UI动效替代"
    example: "door_opening_f0-f2.png"
  
  s3_completed:
    type: "静态图"
    count: 1
    example: "door_opened.png"
```

### 6.3 交互提示视觉统一

**全局视觉语法（避免每处都不一样）**

```yaml
interaction_visual_language:
  rule: "主体永远不变，提示永远叠加"
  
  components:
    outline_overlay:
      description: "细轮廓发光贴花"
      color: "#00F5D4"
      width: "2px"
    
    icon_prompt:
      description: "小图标"
      options:
        - "手形（拾取）"
        - "放大镜（查看）"
        - "脚注符号（《备注》特有）"
      size: "24×24px"
      position: "物件上方"
    
    subtle_pulse:
      description: "透明度呼吸"
      range: "0.8-1.0"
      duration: "1.5s"
```
