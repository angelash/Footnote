# 《备注 / Footnote》美术工作流总纲 v2.0

> **文档性质**：美术生产的最高级别规范文档  
> **适用对象**：主美、美术、技术美术、AI生成操作  
> **最后更新**：2024-12-25  
> **核心理念**：把 AI 当成"可控渲染引擎"，而不是"随机器"

---

## 📌 核心原则

### 规范目标

本规范的目标不是"把图生出来"，而是建立：
- **可复用**：资产能在不同场景重复使用
- **可拼装**：模块化设计，像乐高一样组合
- **可做序列帧**：动画帧之间保持一致性
- **可长期扩展**：新增内容不会破坏现有体系

### 问题归因

常见问题的根本原因是**系统缺失**，而非"提示词不够长"：

| 症状 | 根本原因 | 解决方案 |
|------|----------|----------|
| 风格大体像但体系不一 | 缺少三大圣经约束 | 建立Camera/Lighting/Material Bible |
| 视角不稳定 | 缺少镜头规则 | 固定Camera Bible |
| 序列帧拼不起来 | 每帧从零生成 | 母版锁定+编辑迭代 |
| 场景无法拼装 | 缺少网格语法 | 建立TU系统和占格规则 |
| 资产复用做不起来 | 缺少部件规则 | 建立资产语法和命名规范 |

## 1. 三大圣经（不可动摇的约束）

### 1.1 镜头圣经 Camera Bible

**推荐方案：2.5D 俯视玩具盒（非严格等距）**

```yaml
camera_bible:
  # 视角定义
  perspective:
    type: "3/4俯视"
    angle: "弱透视/近似正交"
    禁止: ["广角", "强景深", "强透视变形"]
  
  # 构图规则
  composition:
    grid_alignment: true  # 地面网格永远对齐画面轴
    rotation: 0           # 禁止每张旋转几度
    horizon: false        # 地平线永远不出现
  
  # 适用说明
  notes:
    - 竖版游戏采用3/4俯视，强调"地面是格子"
    - 立体感靠阴影/高光表达，不靠强透视
    - 严格等距容易在AI输出里角度抖动，弱透视更稳定
```

**视角示意图**
```
┌─────────────────────────────────────┐
│           视角：3/4俯视              │
│                                     │
│         ┌───────────┐               │
│        /           /│               │
│       /───────────/ │   相机位置    │
│       │           │ │   ↖          │
│       │    地面   │/     约30-45°   │
│       └───────────┘                 │
│                                     │
│    禁止：广角、地平线、旋转网格      │
└─────────────────────────────────────┘
```

### 1.2 光照圣经 Lighting Bible

**统一光照是"同一体系"的第一视觉证据**

```yaml
lighting_bible:
  # 主光源
  main_light:
    direction: "左上 → 右下"
    angle: 45°
    intensity: "中等"
  
  # 阴影规则
  shadow:
    type: "软阴影"
    direction: "统一朝右下"
    contact_shadow: "中等强度"
    color: "rgba(0, 0, 0, 0.3)"
  
  # 环境光
  ambient:
    intensity: "固定，避免对比度漂移"
    禁止: ["大面积雾效", "强色调滤镜"]
  
  # 禁止项
  forbidden:
    - "逆光大片"
    - "彩色补光"
    - "电影级强色调"
    - "每张图光向不同"
```

**光照方向示意**
```
        ☀️ 主光源
         ╲
          ╲ 45°
           ╲
    ┌───────╲───┐
    │   物件  ╲ │
    │         ▓│  ← 阴影方向
    └──────────┘
              ↘ 阴影落点
```

### 1.3 材质与细节密度 Material & Detail Budget

**每类材质给一个"最大细节密度"，防止漂移**

```yaml
material_bible:
  # 细节预算定义
  detail_budget:
    wood:
      max_grain_lines: 3-5      # 木纹最多条数
      texture_density: "低"
    stone:
      max_face_variations: 2-3  # 石材面变化
      crack_lines: "极少"
    metal:
      highlight_edges: 1        # 高光边数量
      reflection_bands: 1       # 反光带数量
    fabric:
      fold_levels: 2            # 褶皱层级
      texture: "简化"
  
  # 整体风格
  style:
    feel: "玩具模型质感"
    detail_level: "中低，不过度纹理"
    consistency: "所有资产细节密度必须一致"
  
  # 检查项
  checklist:
    - "纹理复杂度是否在预算内"
    - "材质质感是否统一"
    - "不同资产间细节密度是否一致"
```

## 2. 四张锚定图系统

**立刻提升一致性的关键手段**

每次AI生成都必须以这4张图作为参考输入：

### 2.1 锚定图清单

| 序号 | 锚定图 | 用途 | 要求 |
|------|--------|------|------|
| 1 | **Style Anchor** | 风格锚定 | 最满意的一张代表作 |
| 2 | **Palette Anchor** | 色彩锚定 | 12-24色的色板图 |
| 3 | **Camera Grid Anchor** | 视角锚定 | 地面网格+立方体+小人站位示意 |
| 4 | **Lighting Anchor** | 光照锚定 | 白球/灰球在统一光向下的参考 |

### 2.2 锚定图制作要求

**Style Anchor（风格锚定图）**
```yaml
style_anchor:
  content: "最能代表目标风格的完整场景或角色"
  elements:
    - 完整的材质表现
    - 正确的光影关系
    - 统一的细节密度
  format: "1024×1024 或更大"
  用途: "所有生成都参考此图的整体风格"
```

**Palette Anchor（调色板锚定图）**
```yaml
palette_anchor:
  layout: "色块网格排列"
  colors:
    primary: 4-6色      # 主色调
    secondary: 4-6色    # 辅助色
    accent: 2-4色       # 强调色
    neutral: 2-4色      # 中性色
  labeling: "每个色块标注色值"
  用途: "控制所有资产的色彩范围"
```

**Camera Grid Anchor（视角网格锚定图）**
```yaml
camera_grid_anchor:
  elements:
    - "清晰的地面网格（显示TU单位）"
    - "标准立方体（显示透视规则）"
    - "人物站位参考（显示比例）"
  perspective: "与Camera Bible一致的3/4俯视"
  用途: "锁定所有资产的视角和比例"
```

**Lighting Anchor（光照锚定图）**
```yaml
lighting_anchor:
  objects:
    - "白色球体（显示光源方向）"
    - "灰色立方体（显示阴影逻辑）"
    - "金属球体（可选，显示反光）"
  lighting: "与Lighting Bible一致"
  用途: "统一所有资产的光影表现"
```

### 2.3 锚定图存放位置

```
assets/
└── references/
    └── anchors/
        ├── style_anchor_v001.png
        ├── palette_anchor_v001.png
        ├── camera_grid_anchor_v001.png
        └── lighting_anchor_v001.png
```

## 3. 生成 vs 编辑策略

### 3.1 核心原则

> **所有"系列内容"都用编辑迭代，不要用从零生成**

### 3.2 使用场景判断

| 场景 | 使用方式 | 说明 |
|------|----------|------|
| 创建类别母版 | **生成** | 第一块草地、第一棵树、角色母版 |
| 同角色不同帧 | **编辑** | 基于母版改姿势 |
| 同物件不同变体 | **编辑** | 破损版/染色版/雪覆盖版 |
| 放入场景 | **编辑** | 保持风格一致的融合 |
| 不同主题物件 | **生成** | 需要新的母版 |

### 3.3 编辑迭代工作流

```yaml
edit_iteration_workflow:
  step_1:
    action: "准备母版图"
    input: "已验收的母版资产"
  
  step_2:
    action: "准备四张锚定图"
    input: "Style/Palette/CameraGrid/Lighting Anchor"
  
  step_3:
    action: "组织编辑指令"
    format: |
      基于输入图像，请：
      - 保持[不变部分]完全不变
      - 仅修改[变化部分]为[目标状态]
      - 保持风格、色彩、光照与锚定图一致
  
  step_4:
    action: "验收检查"
    checklist:
      - "不变部分是否真的没变"
      - "变化部分是否符合要求"
      - "整体风格是否一致"
```

## 4. Prompt 模板系统

### 4.1 全局前缀（永远复用）

```
【全局约束 - 必须包含在所有提示词中】

目标：为俯视玩具盒风格2.5D叙事游戏生成可拼装资产

必须遵守：
- 相机：3/4俯视，弱透视/近似正交，画面与地面网格严格对齐
- 光照：左上主光，统一阴影方向与软硬
- 材质：玩具模型质感，细节预算受控（不过度纹理）
- 输出：主体居中、留边距、纯色背景（用于抠图）、无文字无水印
```

### 4.2 资产类型模板

**Ground Tile 生成模板**
```
【参考图】Style Anchor + Palette + Texture Anchor + CameraGrid

【指令】
生成 1×1 TU 的[地面类型] base tile，
纯平铺，无边缘过渡，无显眼装饰点，
纹理颗粒尺度与 Texture Anchor 一致，
光照左上，背景纯绿(#00FF00)用于抠图，
俯视玩具盒风格，禁止透视旋转。
```

**Transition 生成模板**
```
【参考图】源地面base + 目标地面base + CameraGrid

【指令】
生成 1×1 TU 的过渡边 tile：
[源地面]到[目标地面]的[方向]边缘（N/S/E/W edge），
只画边缘形状，中间透明，
接缝可无痕循环，光照左上，禁止新增装饰。
```

**角色帧编辑模板**
```
【参考图】角色母版（当前方向站姿）+ 本帧骨架图

【指令】
在保持角色造型、配色、五官完全一致的前提下，
把姿势改成骨架图所示的[动作帧]，
仅允许修改[变化部位]，其他部位保持不变，
保持脚底基线与pivot不动，背景纯绿(#00FF00)。
```

### 4.3 禁止项清单

```yaml
prompt_forbidden:
  视角:
    - "旋转视角"
    - "改变镜头高度"
    - "透视变形"
  内容:
    - "添加额外道具"
    - "复杂背景"
    - "文字或符号"
    - "水印"
  效果:
    - "强景深"
    - "过度虚化"
    - "电影级色调"
```

```

│   ├── props.yaml                # 物件规格
│   ├── characters.yaml           # 角色规格

│
└── 04_atlas/                     # 合图输出
    ├── tiles_atlas.png
    └── props_atlas.png
```

### 5.2 文件命名规范

```
格式：<category>/<set>/<id>__<size>__<view>__<variant>__v###.<ext>

示例：
tiles/grass/t_grass_base__1x1__top__a__v001.png
tiles/grass/t_grass_to_dirt_edge__1x1__top__n__v003.png
props/village/p_crate__1x1__top__a__v002.png
chars/hero/c_hero_walk__256__down__f03__v005.png
scenes/demo/s_demo_room01__16x9__top__a__v001.png

字段说明：
- category: tiles / props / chars / scenes / ui
- set: 风格集或地区集（village / forest / dungeon）
- id: 固定资产ID（不要随便改）
- size: 占格或画布尺寸（1x1 / 2x2 / 256）
- view: top/down/up/left/right
- variant: a/b/c... 或 n/e/s/w（用于边缘方向）
- v###: 版本号（必填）
```

## 6. 质量控制入口

### 6.1 三张必备测试图

| 测试图 | 用途 | 检查内容 |
|--------|------|----------|
| **Tile Seam Test** | 地块接缝测试 | 同一tile 3×3拼接，检查接缝 |
| **Kit Showcase** | 套件展示 | 一屏放齐该Kit代表资产 |
| **Animation Strip** | 动画条测试 | walk 6帧横排，检查抖动 |

### 6.2 快速验收清单

```yaml
quick_qa_checklist:
  所有资产:
    - [ ] 视角是否符合Camera Bible
    - [ ] 光向是否符合Lighting Bible
    - [ ] 细节密度是否在预算内
    - [ ] 色彩是否在Palette范围内
    - [ ] 背景是否可抠
    - [ ] 是否有多余元素
  
  地块专用:
    - [ ] 接缝是否无痕
    - [ ] 是否有强特征在边缘
  
  角色专用:
    - [ ] Pivot是否在正确位置
    - [ ] 基线是否一致
    - [ ] 轮廓是否稳定
```

## 附录B：术语表

| 术语 | 定义 |
|------|------|
| **TU (Tile Unit)** | 地块单位，基本网格单元 |
| **Footprint** | 物件占地格数，用于碰撞和摆放 |
| **Visual Bounds** | 可视边界，画面上实际占用大小 |
| **Pivot** | 锚点，对齐用的参考点 |
| **Kit** | 套件，同一主题的完整资产集合 |
| **Anchor** | 锚定图，用于保持风格一致的参考图 |
| **Base** | 基底层，地面或物件的主体 |
| **Overlay** | 覆盖层，叠加的装饰或效果 |
| **Occluder** | 遮挡层，会挡住角色的前景元素 |
