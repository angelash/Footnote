# 配置化场景搭建流程规范（PNG物件 → YAML组装 → Phaser运行时）

目标：用**可批量生产**的方式搭建 Zone 场景。

核心思想：

- **物件资产**：以 PNG（像素风为主）形式产出，可程序化生成
- **资源注册**：把 PNG 的路径统一注册成可引用的 `texture key`
- **场景配置**：用 YAML 描述“背景/物件/层级/交互/动画”
- **运行时组装**：`SceneAssembler` 读取 YAML，自动创建 Phaser 对象并挂交互回调

---

## 目录与文件约定

- **PNG 物件输出目录**：`assets/images/pixel/`
  - 图标：`assets/images/pixel/icons/...`
  - 精灵条带（spritesheet strip）：`assets/images/pixel/sprites/...`
  - 序列帧：`assets/images/pixel/sequences/...`
- **像素 PNG 生成脚本**：`scripts/generate_pixel_assets.py`
- **像素资源注册表**：`src/data/pixelAssets.ts`
  - `PIXEL_IMAGE_ASSETS`: image 资源 key → url
  - `PIXEL_SPRITESHEETS`: spritesheet 资源 key → url + frameWidth/frameHeight
- **场景配置目录**：`src/data/scenes/`
  - 一个 Zone 一个 YAML，例如：`c0_z1.yaml`
  - 场景入口：`src/data/scenes/index.ts`（按 zoneId 映射到 YAML）
- **场景组装器**：`src/systems/scene/SceneAssembler.ts`
- **场景使用点**：`src/scenes/GameScene.ts`（`_buildZoneFromConfig`）

---

## 一键命令（推荐）

- **生成像素 PNG（默认参数）**：`npm run generate:pixel-assets`
- **生成像素 PNG（图标 128×128 / 色数≤24 / 带序列帧）**：`npm run generate:pixel-assets:128`

> 说明：128×128 是通过 `scale=8`（底图 16×16）放大得到，仍然保持像素风锐利边缘。

## 场景配置 YAML 规范

### 基本结构

- `id`: ZoneId（如 `C0-Z1`）
- `title`: 标题（可选）
- `background`: 背景配置（可选）
- `objects`: 物件数组（必填）

示例见：`src/data/scenes/c0_z1.yaml`

### background 字段

- `texture`: Phaser texture key（例如 `placeholder_bg` 或你注册的背景 key）
- `x/y`: 坐标（默认 0）
- `origin`: `[ox, oy]`（默认 `[0,0]`）
- `displaySize`: `[w, h]`（可选）
- `alpha`: 透明度（可选）

### objects 字段

每个 object 是一个可渲染物件：

- `id`: 唯一ID（建议 `snake_case`，用于 debug / testid / action 定位）
- `type`: `image` | `sprite`
- `texture`: Phaser texture key（来自 `src/data/pixelAssets.ts` 的注册）
- `x/y`: 坐标
- `scale`: 缩放（可选）
- `depth`: 层级（可选，越大越靠前）
- `alpha`: 透明度（可选）
- `rotation`: 旋转（可选）
- `origin`: `[ox, oy]`（可选）
- `frame`: sprite 初始帧（可选）
- `label`: 小标签（可选，用于调试/临时提示）
- `labelOffset`: `[dx, dy]`（可选）
- `interactive`: 交互（可选）
- `animation`: 动画（仅 `type: sprite` 时可用，可选）

#### interactive

- `cursor`: 是否显示手型光标（默认 true）
- `testid`: 测试定位用（可选）
- `action`: 点击动作（可选）
  - `type`: `dialogue` | `card` | `gotoZone` | `none`
  - `dialogue`: `speaker` + `text`
  - `card`: `cardId`
  - `gotoZone`: `zoneId`

#### animation（sprite）

- `key`: 动画 key（同一个 texture 上复用）
- `frameRate`: 帧率（默认 6）
- `repeat`: 重复次数（默认 -1 无限）
- 帧选择二选一：
  - `frames: { start, end }`
  - `frameNumbers: [0,2,4,...]`

## 铺量生产步骤（Checklist）

### A. 产出/新增 PNG 物件

- **生成**（推荐）：运行 `npm run generate:pixel-assets:128` 或调整 `scripts/generate_pixel_assets.py`
- **或手动加入**：把 PNG 放入 `assets/images/pixel/...` 对应子目录
- **命名**：
  - 文件：`px_{category}_{name}.png`（例如 `px_item_keycard.png`）
  - Phaser key：与文件名对应（例如 `px_item_keycard`）

### B. 注册资源 key（必须）

编辑：`src/data/pixelAssets.ts`

- 新增 image：
  - 在 `PIXEL_IMAGE_ASSETS` 加 `key: url`
- 新增 spritesheet：
  - 在 `PIXEL_SPRITESHEETS` 加 `key: { url, frameWidth, frameHeight }`

> 注意：PreloadScene 会自动遍历这两个表加载资源，所以这里是单一真源（SSOT）。

### C. 新增/修改场景 YAML

新增：`src/data/scenes/{zoneId}.yaml`（例如 `c0_z2.yaml`）

- `texture` 一律填 **资源 key**（不要写路径）
- 交互统一用 `interactive.action` 声明

### D. 注册场景入口映射（必须）

编辑：`src/data/scenes/index.ts`

- import 对应 YAML：`import c0z2Yaml from './c0_z2.yaml?raw'`
- 在 `SCENE_YAML_BY_ZONE_ID` 加 `'C0-Z2': c0z2Yaml`

### E. 运行验证

- `npm run typecheck`
- 启动后进入该 Zone（目前通过菜单进入 `C0-Z1`，你可以扩展为从菜单选择 Zone）

---

## 运行时行为约定

- `GameScene` 会优先走配置化场景：
  - 找到 YAML → `SceneAssembler.build(cfg)` 生成对象
  - 找不到 YAML → 回退到旧的硬编码交互点（开发阶段兜底）
- Zone 切换时会先销毁旧的 assembled objects，避免泄漏

---

## 常见坑（铺量时很省时间）

- **新增 PNG 但 YAML 引用不到**：通常是忘了在 `src/data/pixelAssets.ts` 注册 key
- **spritesheet 动画不动**：检查 `frameWidth/frameHeight` 是否匹配 strip 的单帧尺寸
- **点击无响应**：确认 `interactive.action.type` 不是 `none`，且对象没有被别的对象遮挡（depth）
- **像素风变糊**：不要用线性缩放；必须 NEAREST（我们生成脚本已保证）
