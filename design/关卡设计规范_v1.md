## 📌 设计原则

### 核心理念

1. **叙事即关卡**：每个Zone都是故事的一部分，不存在纯填充内容
2. **五分钟单元**：单Zone体验控制在5-10分钟，适配移动端碎片时间
3. **有意义的选择**：玩家的每个决策都应有可感知的后果
4. **渐进复杂度**：从简单交互到多系统组合使用

### 设计约束

| 约束 | 数值 | 原因 |
|------|------|------|
| 单Zone时长 | 5-10分钟 | H5碎片化体验 |
| 单Zone对话 | ≤15轮 | 避免阅读疲劳 |
| 单Zone交互点 | 3-8个 | 保持聚焦 |
| 单Zone能力使用 | ≤3次 | 避免能力滥用 |
| 章节Zone数 | 4-8个 | 保持节奏 |

## 1. Zone分类与模板

### 1.1 Zone类型定义

| 类型 | 代码 | 特征 | 占比 |
|------|------|------|------|
| **生活** | LIFE | 日常、对话、氛围 | 35% |
| **异常** | ANOM | 结构问题、解谜 | 25% |
| **冲突** | CONF | 紧张、抉择、后果 | 20% |
| **过渡** | TRAN | 连接、转场、铺垫 | 15% |
| **终局** | CLIMAX | 高潮、结算 | 5% |

### 1.2 生活型Zone模板

```yaml
zone_template_life:
  structure:
    - phase: 入场
      duration: 30s
      content: 环境描述、氛围建立
    
    - phase: 主交互
      duration: 3-5min
      content: NPC对话、物品获取、日常互动
    
    - phase: 收尾
      duration: 30s
      content: 离场提示、下一目标暗示
  
  elements:
    npcs: 1-2  # 可对话NPC数
    items: 1-3  # 可获取物品数
    exits: 1-2  # 出口数
  
  rhythm:
    tension_curve: low → low → low
    ability_use: none
```

#### 示例：C0-Z2 早餐小店

```yaml
zone: C0-Z2
type: life
title: 早餐小店

layout:
  size: [750, 1200]  # 单屏+轻微滚动
  background: bg_shop
  
objects:
  - id: shopkeeper
    type: npc
    position: [400, 600]
    dialogue: SHOP_KEEPER_C0
    
  - id: table_food
    type: interactive
    position: [300, 800]
    action: choice
    options:
      - text: "老样子，固定套餐"
        result: normal
      - text: "来份没人点的那个"
        result: r_plus_1  # 无收益选择
        
  - id: qilan_background
    type: npc_passive
    position: [550, 900]
    note: 栖蓝路过，不可交互
    
exits:
  - direction: south
    target: C0-Z3
    
foreshadow:
  - F05_opportunity  # 无收益选择机会点
```

### 1.3 异常型Zone模板

```yaml
zone_template_anomaly:
  structure:
    - phase: 发现
      duration: 1min
      content: 异常迹象、玩家困惑
    
    - phase: 探索
      duration: 3-5min
      content: 使用能力、收集信息
    
    - phase: 解决/理解
      duration: 1-2min
      content: 突破或接受、获得线索
  
  elements:
    anomaly_points: 1-3
    ability_triggers: 1-2
    hidden_items: 0-2
  
  rhythm:
    tension_curve: low → high → medium
    ability_use: required
```

#### 示例：C2-Z2 薄墙巷口（重访）

```yaml
zone: C2-Z2
type: anomaly
title: 薄墙巷口（重访）

prerequisite:
  - ability: depth_perception
  - foreshadow: F01_planted

layout:
  size: [750, 1334]
  background: bg_alley
  
anomaly_design:
  description: |
    玩家之前在C0-Z3听到过回声但系统说"正常"
    现在有了深度感知，可以看到墙内空腔
    
  discovery:
    trigger: player_approach_wall
    hint: 内心独白"之前在这里..."
    
  ability_use:
    required: depth_perception
    target: wall_section_1
    reveal: 墙内空腔结构
    
  resolution:
    foreshadow_recall: F01
    card_obtain: CARD_WALL_SECRET

objects:
  - id: wall_section_1
    type: anomaly_point
    position: [375, 700]
    perception_reveal:
      visual: 线框显示空腔
      text: "这里...有空间"
      
exits:
  - direction: north
    target: C2-Z3
```

### 1.4 冲突型Zone模板

```yaml
zone_template_conflict:
  structure:
    - phase: 铺垫
      duration: 1min
      content: 紧张氛围、stakes建立
    
    - phase: 对峙
      duration: 2-4min
      content: 关键对话、选择呈现
    
    - phase: 抉择
      duration: 1min
      content: 做出选择
    
    - phase: 后果
      duration: 1-2min
      content: 即时反馈、状态变化
  
  elements:
    conflict_parties: 2+
    choices: 2-3
    consequences: clear
  
  rhythm:
    tension_curve: medium → high → peak → medium
    ability_use: optional_meaningful
```

| 喘息类型 | 时长 | 内容 |
|----------|------|------|

| **角色互动** | 3min | 深化关系、获得线索 |
| **环境探索** | 5min | 自由探索、无压力 |

## 3. 空间设计规范

### 3.1 Zone尺寸标准

| 类型 | 宽度 | 高度 | 滚动 |
|------|------|------|------|
| **紧凑** | 750px | 1334px | 无 |
| **标准** | 750px | 1600-2000px | 轻微 |
| **宽广** | 750px | 2500-3000px | 明显 |

### 3.2 空间布局原则

```
┌────────────────────────────────────────┐
│                                        │
│              入口区域                   │  玩家初始位置
│              (安全)                     │
│                                        │
├────────────────────────────────────────┤
│                                        │
│              主交互区                   │  核心内容
│              (焦点)                     │  NPC、关键物品
│                                        │
├────────────────────────────────────────┤
│                                        │
│              出口/目标区                │  下一步指引
│              (引导)                     │
│                                        │
└────────────────────────────────────────┘
```

### 3.3 视觉引导

| 元素 | 用途 | 实现方式 |
|------|------|----------|
| **光源** | 引导注意力 | 高光区域 |
| **色彩** | 区分重要性 | 强调色点缀 |
| **动效** | 吸引交互 | 微动画 |
| **留白** | 强调焦点 | 周围简化 |

## 4. 交互点设计

### 4.1 交互类型

| 类型 | 图标 | 触发 | 反馈 |
|------|------|------|------|
| **NPC对话** | 对话气泡 | 点击 | 对话框 |
| **物品检视** | 放大镜 | 点击 | 描述卡片 |
| **物品获取** | 闪光 | 点击 | 获得动画 |
| **深度目标** | 透视圆环 | 长按 | 透视效果 |
| **介入目标** | 拖拽箭头 | 拖拽 | 结构变化 |
| **传送点** | 出口标记 | 点击 | Zone切换 |

### 4.2 交互密度

| Zone类型 | 交互点数 | 必要交互 | 可选交互 |
|----------|----------|----------|----------|
| 生活 | 3-5 | 1-2 | 2-3 |
| 异常 | 4-6 | 2-3 | 2-3 |
| 冲突 | 3-4 | 2-3 | 0-1 |
| 过渡 | 2-3 | 1 | 1-2 |

### 4.3 交互反馈等级

| 等级 | 视觉 | 音效 | 用途 |
|------|------|------|------|
| **轻微** | 微光 | 无 | 可选物品 |
| **标准** | 高亮 | sfx_interact | 普通交互 |
| **强调** | 动画+光晕 | sfx_important | 关键物品 |
| **异常** | 扭曲+闪烁 | sfx_anomaly | 深度目标 |

## 5. 解谜设计

### 5.1 解谜类型

| 类型 | 难度 | 示例 |
|------|------|------|
| **观察型** | ★☆☆ | 找到隐藏信息 |
| **组合型** | ★★☆ | 连接多个线索 |
| **逻辑型** | ★★☆ | 推理正确顺序 |
| **能力型** | ★★★ | 使用特定能力 |
| **时间型** | ★★★ | 需要回溯解决 |

### 5.2 解谜层次

```
问题呈现 → 线索收集 → 尝试解决 → 成功/失败 → 反馈学习

每个解谜应该有:
1. 明确的问题（玩家知道要解决什么）
2. 可达的线索（不需要穷举）
3. 多种尝试（允许试错）
4. 清晰反馈（知道对错）
```

### 5.3 卡住预防

| 机制 | 触发 | 内容 |
|------|------|------|
| **轻提示** | 停滞60s | "也许需要仔细看看..." |
| **中提示** | 停滞180s | 具体方向提示 |
| **强提示** | 停滞300s | 接近答案的提示 |
| **解决方案** | 主动请求 | 直接告知解法 |

## 6. 分支与后果

### 6.1 分支类型

| 类型 | 影响范围 | 示例 |
|------|----------|------|
| **对话分支** | 当前对话 | 不同回应 |
| **行为分支** | 当前Zone | 不同处理方式 |
| **状态分支** | 跨Zone | 影响后续内容 |
| **结局分支** | 全局 | 影响最终结局 |

### 6.2 后果设计

```yaml
choice_consequence:
  immediate:  # 即时反馈
    - dialogue_change  # 对话变化
    - animation_play   # 动画播放
    - sound_effect     # 音效
    
  short_term:  # 短期后果
    - npc_attitude     # NPC态度变化
    - zone_state       # Zone状态变化
    - item_obtain      # 物品获得/失去
    
  long_term:  # 长期后果
    - counter_change   # R/P/W变化
    - foreshadow_state # 伏笔状态
    - ending_flag      # 结局相关
```

### 6.3 后果可视化

| 后果类型 | 可视化方式 |
|----------|------------|
| R值增加 | 无直接显示（通过系统语气变化） |
| P值增加 | 轻微画面抖动 |
| 伤痕创建 | 裂缝动画 |
| NPC态度 | 对话语气变化 |
| Zone状态 | 环境视觉变化 |

## 7. Zone配置格式

### 7.1 完整配置示例

```yaml
# src/data/zones/c2_z4.yaml
zone:
  id: C2-Z4
  chapter: C2
  title: 栖蓝的修补摊
  type: life
  duration: 6min
  
  # 前置条件
  prerequisites:
    zones_completed: [C2-Z3]
    abilities: [depth_perception]
  
  # 布局
  layout:
    background: bg_repair_stall
    size: [750, 1800]
    player_spawn: [375, 1600]
    camera:
      initial: [375, 900]
      bounds: [0, 0, 750, 1800]
  
  # 对象
  objects:
    - id: qilan
      type: npc
      position: [400, 800]
      sprite: char_qilan_idle
      interactive:
        dialogue: QILAN_C2_Z4
        
    - id: broken_signpost
      type: interactive
      position: [200, 600]
      sprite: obj_signpost_broken
      label: 倒下的路标
      interactive:
        action:
          type: choice
          options:
            - text: 帮她扶正
              result:
                r_change: +2
                dialogue: QILAN_THANKS
                world_state:
                  signpost_fixed: true
            - text: 这不是我的工作
              result:
                dialogue: QILAN_UNDERSTAND
                world_state:
                  signpost_fixed: false
    
    - id: repair_tools
      type: item
      position: [500, 700]
      sprite: item_tools
      interactive:
        action:
          type: inspect
          card: CARD_REPAIR_TOOLS
  
  # 出口
  exits:
    - id: exit_south
      position: [375, 1750]
      target: C2-Z5
      condition: dialogue_complete
  
  # 伏笔
  foreshadows:
    plant: [F05]  # 无收益选择首次明确
    
  # BGM/环境
  audio:
    bgm: bgm_drifter
    ambience: amb_drifter_area
    
  # 事件
  events:
    on_enter:
      - play_dialogue: QILAN_INTRO
    on_signpost_fixed:
      - update_world_state
      - play_sfx: sfx_interact
```
